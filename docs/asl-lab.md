# AllStarLink test lab (profile `asl-lab`)

A contained, private AllStarLink-style lab on the rig, so that DV-Router's future
edge `dv-edge-allstar` can be tested against a real Asterisk / app_rpt and so that
real IAX2 byte vectors are captured. Nothing leaves the rig host: the rig network
is `internal`, node numbers are private test numbers, secrets are fixtures, the
only name server is the lab's own. The first use is capture-only (Asterisk to
Asterisk and Asterisk to an IAX2 client); the edge does not exist yet and node E
is its stand-in.

## Run

```
scripts/run.sh --profile asl-lab -m asl_lab                  # about 3 minutes
DVT_ASL_LONG=1 scripts/run.sh --profile asl-lab -m asl_lab   # + the 75 s call (ts16 wrap), about 4.5 minutes
scripts/run.sh --profile asl-lab --keep -m asl_lab -- cases/test_asl_lab.py   # leave the lab up, look around
scripts/run.sh --down                                        # and clean up
```

`--profile asl-lab` on its own starts the tester and the four lab hosts only (no
reflector, no transcoder, no `TRANSCODER_IMAGE`); next to other profiles the lab
hosts simply join the rig. Everything goes through `scripts/run.sh` (capped scope
`dvt-rig.scope`, one rig at a time). `touch out/x` and `btrfs filesystem usage /`
before a run, as for every run. Every scenario takes seconds except `long_call`.

Build: `run.sh` builds `dvt-allstar:local` first when it is missing
(`rig/Dockerfile.allstar`, the pinned ASL3 packages) and then `dvt-asl-lab:local`
(`rig/Dockerfile.asl-lab`: that image plus `python3`, `tcpdump` and `dnsmasq-base`
from the distro mirror, the only internet use).

## Hosts

| Service | Address | Role |
|---------|---------|------|
| asl-reg | 172.30.0.41 | registrar (IAX2 REGREQ, Asterisk users per node) and the lab DNS zone (dnsmasq) |
| asl-a | 172.30.0.42 | node 199901: the caller |
| asl-b | 172.30.0.43 | node 199902: the callee with its own link list |
| asl-e | 172.30.0.44 | node 299901: stand-in for the edge under test (anonymous `radio`, accounts `acct`, `acct-ct`) |

Addresses are `<DVT_NET>.41` to `.44`. In documents and vectors the placeholders
are 192.0.2.x. Node numbers 199901, 199902 and 299901 are private test numbers
(`DVT_ASL_NODE_A/B/E`); they are not assigned on the real network and no node
registers anywhere real (`res_rpt_http_registrations` is `noload`, the portal
registration file is empty, no `statpost`). Each host has its own address, so all
of them use the same IAX2 UDP port, `DVT_ASL_IAX_PORT` (default 4569; the DNS zone
and the registrar users follow it). Limits: `limits-small` for asl-reg,
`limits-medium` for the nodes.

Secrets are fixtures, written in the clear because they protect nothing:
`test-secret-not-real` for the `acct` users and for the registrar users
(`dvtest.asl_lab.ACCT_SECRET`, `REG_SECRET`; `DVT_ASL_ACCT_SECRET` /
`DVT_ASL_REG_SECRET` replace them in the hosts, restricted to `[A-Za-z0-9_.-]`).
A wrong secret in the registration scenario is `wrong-secret-not-real`.

Each lab host runs the **lab agent** (`rig/asl-lab-agent.py`, HTTP on port 8099, rig
network only, stdlib python) because the tester has no docker socket. It runs
allow-listed Asterisk CLI commands (`rpt fun|cmd|playback|lstats|...`, `iax2 show`,
`channel originate`, `dialplan set global`, `module reload chan_iax2`), starts and
stops one `tcpdump` per scenario, takes the tone file, writes the `register =>`
lines, and hands pcaps and recordings back. The client side is `dvtest/asl_lab.py`.

## Node-name lookup (DNS), as app_rpt does it

`rpt.conf` of every node: `node_lookup_method = dns` and `dns_node_domain =
nodes.asl.test` (`DVT_ASL_DOMAIN`; `.test` is reserved, so it never resolves
anywhere real). `[nodes]` lists only the node itself
(`199901 = radio@127.0.0.1:4569/199901,NONE`). app_rpt resolves any other node
number of 4 to 6 digits with an SRV query and then an A query:

```
_iax._udp.<node>.<domain>   SRV  0 0 <port> <node>.<domain>        TTL 30
<node>.<domain>             A    <node ip>                         TTL 30
<node>.<domain>             TXT  "NN=<node>" "IP=<ip>" "PT=<port>" (as ASL publishes it for debugging)
```

The zone is generated by `rig/asl-lab-entry.sh` from `DVT_ASL_ZONE` (compose) into
dnsmasq `srv-host`, `host-record` and `txt-record` lines; `local=/<domain>/` makes
unknown nodes NXDOMAIN. app_rpt never asks for the TXT record (the `dns_zone`
scenario asks it from the tester). The hosts use the registrar as their only name
server (`dns:` and `dns_search: ["."]` in `rig/compose.yml`, so no host search
domain leaks into a query).

The callee validates the claimed caller with the same lookup: node 199901 calling
node 299901 as `radio` must be found in DNS at the address the call comes from
(`Rpt()` without option `X`). Account users run `Rpt(<node>,X)`, which skips that
check.

## Scenarios

Each scenario names itself on every host (recording directory), runs `tcpdump` on
the hosts listed, and on exit copies the pcaps and recordings to
`out/<run>/asl-lab/<scenario>/`:

```
<host>.pcap            full capture (never committed)
<host>.frames.json     dvtest.iax2_frames, first 3 frames per type (+ ts16 wrap frames) and the DNS messages
rec/<host>/<node>-from-<peer>-HHMMSS-rx.sln   what that host received on an inbound call (raw 8 kHz S16LE)
rec/<host>/...-mix.sln                        both directions mixed
scenario.json          pcap sizes, recording names, notes (tone sha256, registry lines, rpt variables)
```

| Scenario | What happens | Frame types it yields |
|----------|--------------|-----------------------|
| `link-dns` (A, E, reg) | A dials E (`rpt fun 199901 *3299901`) as anonymous `radio`; the node number comes from the lab zone; A keys the 1 kHz tone; A hangs up | NEW (without and with call token), CALLTOKEN, ACCEPT, ANSWER, ACK, TEXT (`!NEWKEY1!`, `T`, `L`, `!!DISCONNECT!!`), voice full + mini, CNG, CONTROL RADIO_UNKEY, STOP_SOUND, HANGUP; DNS SRV / A |
| `account-md5` (A, E) | A originates `IAX2/acct:<secret>@E/299901` running `Rpt(199901,X)`, and the same as `acct-ct`; tone from A | AUTHREQ (md5, challenge), AUTHREP (MD5_RESULT), NEW/CALLTOKEN with a user that needs no token and one that does |
| `callee` (A, B, E) | B links A (its own link list), then E originates to B (mode C); tone from E reaches B and, through B, A | the above plus `L T199901` sent to the edge, a three-node chain |
| `loop` (A, B, E) | three dials issued together close A to B to E to A before any L message has been exchanged | NEW x3, L lists with a node listed twice |
| `legacy-key` (E) | the tester's IAX2 client (`dvtest.proto.iax2.Client`, ulaw) calls E as account `acct` without call token, legacy `!NEWKEY!`, keys, sends the tone, unkeys; E plays the tone to it; the client sends PING and LAGRQ | RADIO_KEY, RADIO_UNKEY both ways, `!NEWKEY!`, PING/PONG, LAGRQ/LAGRP |
| `registration` (A, reg) | A registers at the registrar with `register => 199901:<secret>@<reg>`, then with a wrong secret | REGREQ x3, REGAUTH, REGACK (refresh 180), REGREJ |
| `dns-zone` (reg) | the tester asks SRV, A, TXT of node 299901, an unknown node, and the registrar name | DNS only |
| `long-call` (A, E; `DVT_ASL_LONG=1`) | A links E and plays a 70 s tone: one call of 75 s | mini frame `ts16` wrap, natural PING/PONG every 21 s and LAGRQ/LAGRP every 10 s |

### Audio

The tone is generated in the case (`dvtest.asl_lab.tone_ulaw`): a 1 kHz sine,
amplitude 8000, 8 kHz, mu-law, 3 s (24000 bytes, sha256 in `scenario.json` and
asserted), uploaded through the agent to `/var/lib/asterisk/sounds/dvt/tone1k.ulaw`
and played with `rpt playback <node> /var/lib/asterisk/sounds/dvt/tone1k` (app_rpt
keys its transmitter and sends the audio to every link). The far side records what
it receives with `MixMonitor(<mix>,r(<rx>))` in the inbound dialplan
(`rig/config/asl-lab/extensions.conf`); `.sln` is raw, so there is no header to
finalise. The cases take the frames above 500 rms, require at least 1.5 s of them,
rms above 1000 and at least 0.9 of the power at 1 kHz (a clean pass measures rms
4036 and 1.00).Telemetry (`telemdefault = 0`) is off so that the "node ... connected" speech does not
queue in front of the tone; `T` text messages are sent regardless.

### Provoking things

- **ts16 wrap**: a mini frame carries the low 16 bits of the call timestamp in
  milliseconds (`ts16`), so it wraps after 65.536 s of one call. The case plays a 70 s
  tone over one link and waits 73 s; the capture then holds `ts16` 0xFFF0 followed by
  0x0004 (20 ms steps). Asterisk did **not** send a new full voice frame at the wrap
  (one full voice frame opens the stream, everything after is mini; the receiver
  extends the timestamp from the 32-bit timestamps of full frames such as LAGRQ,
  PING and ACK, which come every 10 s). A client-side forced wrap is not needed.
- **PING / LAGRQ**: Asterisk sends LAGRQ every 10 s and PING every 21 s, both ways
  (the long call). The `legacy-key` case also sends both from the client for a
  quick answer.
- **loop**: app_rpt checks the target against the caller's link tree only, and a
  tree is learned from the peers' `L` messages 150 ms or more after a link comes
  up. Three dials in parallel threads close the triangle before that.
- **REGREJ**: a second `register =>` line with a wrong secret, written and applied
  through the agent (`module reload chan_iax2.so`).

## Knobs that matter (files in `rig/config/asl-lab/`, rendered at start)

`iax.conf` of a node (`iax-node.conf.in`, modelled on the ASL3 default):

| Setting | Lab value | Why it matters |
|---------|-----------|----------------|
| `bindport` | `DVT_ASL_IAX_PORT` (4569) | one port for all hosts, each its own address; it must precede `bindaddr` in the file or the socket still binds 4569 |
| `disallow=all`, `allow=ulaw,adpcm,gsm` | ASL3 default | only ulaw is ever negotiated between lab nodes; the client in `legacy-key` offers ulaw |
| `jitterbuffer=yes`, `forcejitterbuffer=yes`, `maxjitterbuffer=1000`, `resyncthreshold=500`, ... | ASL3 default | the receiver delays text and voice; the app_rpt comment on text held back by a jitter buffer applies |
| `delayreject=yes`, `autokill=yes`, `maxcallnumbers_nonvalidated=10` | ASL3 default | |
| `[radio]` `type=user`, no `secret`, `context=radio-secure`, `transfer=no` | ASL3 default | the anonymous node-to-node user; **`requirecalltoken` is not set**, Asterisk's default applies (see surprises) |
| `[radio-nt]` | `requirecalltoken=no` | same user for clients that cannot do call tokens |
| `[acct]`, `[acct-ct]` | `auth=md5`, `secret=test-secret-not-real`; `acct` has `requirecalltoken=no` | account users with the md5 challenge, context `radio-acct` (`Rpt(node,X)`) |
| `register =>` | none at start; written per scenario to `/etc/asterisk/dvt-register.conf` | nothing registers unasked |

`rpt.conf` of a node (`rpt.conf.in`): `[general] node_lookup_method=dns`,
`dns_node_domain`; `[nodes]` with the node itself; node stanza with
`rxchannel=USRP/127.0.0.1:<tx>:<rx>` (chan_usrp to a dummy address, so no radio and no
DAHDI), `duplex=1`, `hangtime=0`, `telemdefault=0`, `linkpost_time=10` (the shortest
period of the `L` link list, default 30), `context=radio-local`, and `[functions]`
with `ilink` 1, 2, 3, 6, 8, 12, 13 so that `rpt fun <node> *3<other>` (transceive),
`*1<other>` (disconnect) and `*6` (disconnect all) work from the CLI. Not set, on
purpose: `statpost_url`, registrations, `idrecording`.

Registrar (`iax-registrar.conf.in`): one `type=friend`, `host=dynamic`, `auth=md5`
user per node number, `minregexpire = maxregexpire = 180` (the registrar answers
REFRESH 180 as the ASL manual's example shows). The module list is the ASL3 one
(`autoload=no`) plus `app_mixmonitor` and `res_clioriginate`; `chan_usrp` on, USB
radios and `res_rpt_http_registrations` off.

Dialplan (`extensions.conf`): inbound calls of `radio` land in `[radio-secure]`
(hang up unless the called number is this host's node; record; `Rpt(<node>)`),
accounts in `[radio-acct]` (`Rpt(<node>,X)`). The global `DVT_SCEN` names the
recording directory.

## Byte vectors for the parser tests

`python3 -m dvtest.iax2_frames <pcap> -o <json> [--limit N] [--anon] [--port 4569]`
(`dvtest/iax2_frames.py`, stdlib only, unit tests in `cases/unit/test_iax2_frames.py`)
lists every IAX2 datagram of a capture with its decoded header, its information
elements and the **whole datagram as hex**, grouped by frame type
(`iax.NEW`, `iax.AUTHREQ`, `control.RADIO_KEY`, `text`, `voice.full`, `voice.mini`,
`cng`, `meta`, ...), plus `summary` (counts), `ts16_wraps` (the mini frames
before and after each wrap) and `dns` (the DNS messages, SRV / A / TXT decoded).
`--limit N` keeps N frames per type and always the wrap frames; `--anon` rewrites
the addresses of the JSON fields to 192.0.2.x. The hex is the wire bytes as
captured: the rig addresses (172.30.0.x) are inside `APPARENT_ADDR` of REGACK and
in the A records of the DNS answers, and the call-token strings are Asterisk's
(`<unix time>?<hex hash>`).

Selected small vector files are committed in `baselines/asl-lab/` (see the README
there); the pcaps stay in `out/` (ignored).

## Surprises

Things the capture showed that the specs and the app_rpt reading did not make obvious:

1. **Call token even when "not required".** Asterisk's own client opens every
   NEW with an empty CALLTOKEN IE (type 54, length 0); the server answers with a
   CALLTOKEN frame and the client repeats the NEW with the token, also for a
   user with `requirecalltoken=no`. `requirecalltoken=no` only means that a NEW
   *without* the IE is accepted (the tester's client does exactly that). ASL's
   `[radio]` does not set it, so a third-party node must do the exchange. Frame
   order: NEW(empty token), CALLTOKEN, NEW(token) with the same call number.
   The token is ASCII `<unix time>?<40 hex>`; REGREQ carries the same IE, and the
   third REGREQ (with MD5_RESULT) carries an empty one again.
2. **No RADIO_KEY in new mode.** Between two ASL3 nodes both sides send `!NEWKEY1!`
   (a TEXT frame with a trailing NUL) right after ANSWER; the first voice frame is
   the key. Only RADIO_UNKEY is sent, always followed by a CNG frame (type 10),
   and by a STOP_SOUND control (subclass 255 = -1) after ANSWER. RADIO_KEY /
   RADIO_UNKEY pairs, repeated every 2 s, appear only with a legacy peer
   (`!NEWKEY!`): the client in `legacy-key` gets `!NEWKEY1!` and `!NEWKEY!` back
   to back.
3. **Text frames always carry the NUL**, also the exact 15 byte `!!DISCONNECT!!`.
   `T <node> COMPLETE` and `T <node> CONNECTED,<a>,<b>` are sent although
   `telemdefault = 0`; `L ` (empty) is exchanged three times within 0.5 s of a link coming up (two from
   the caller, one from the callee), then every `linkpost_time`. A legacy account shows up in the peer's list as
   `T1999` (its caller id number).
4. **NEW has information elements that are not in RFC 5456**: IE 57 (CALLINGANI2, 4
   bytes, zero; named so by the ASL1 design note, Asterisk's own constant) in every NEW from
   Asterisk 22, plus FORMAT2 / CAPABILITY2 (56 / 55: a version byte and an 8 byte mask) next to
   FORMAT / CAPABILITY. Order in the NEW of app_rpt as caller: VERSION, CALLED_NUMBER,
   CODEC_PREFS (ASCII `DGC`), CALLING_NUMBER, CALLINGPRES, CALLINGTON, CALLINGTNS, CALLINGANI2,
   LANGUAGE, USERNAME, FORMAT, FORMAT2, CAPABILITY, CAPABILITY2, ADSICPE, DATETIME, CALLTOKEN
   (empty, then the token). No CALLING_NAME, no DNID. ACCEPT carries FORMAT and FORMAT2 only.
   AUTHREQ carries USERNAME, AUTHMETHODS (2 = md5) and a CHALLENGE that is a decimal string of
   nine digits. PONG carries the six RR_* elements (jitter, loss, packets, delay, dropped, out of
   order). REGACK's APPARENT_ADDR is 16 bytes, a `sockaddr_in`: family `02 00` (host order,
   little endian here), port and address in network order, 8 zero bytes.
5. **Codec: only ulaw.** ASL's list is ulaw, adpcm, gsm and Asterisk picks the first
   one it shares; every call and every voice frame in all scenarios is ulaw, 160
   bytes per 20 ms. The existing rig node (`allstar`, slin) and this lab differ:
   the lab follows ASL3's defaults.
6. **First voice frame is a full frame, the rest are mini** (and no full voice
   frame appears at the ts16 wrap, see above). Mini frames are the 2 byte source
   call number (F bit clear), the 2 byte ts16 and the payload. No trunk (meta) frames.
7. **PING every 21 s and LAGRQ every 10 s, both directions at once**; ACKs echo
   the timestamp of the frame they acknowledge. No retransmission (retrans bit),
   no VNAK in any scenario.
8. **app_rpt probes DNS while a node number is typed.** `rpt fun 199901 *3299901`
   resolved SRV for `1999`, `19990` (both NXDOMAIN) before `199902`, because
   the CLI feeds the digits one by one; only the final lookup is followed by an
   A query. TXT is never asked.
9. **The loop forms**: with parallel dials each node has two direct links and the
   node that closes the loop lists the same node twice in `RPT_LINKS`
   (`T199902,T199901,T199902`); nothing breaks the loop.
10. **Recording headers**: `MixMonitor` to `.wav` leaves a header with zero lengths
    until the channel is gone (a file fetched right after hangup is not a valid
    WAV); `.sln` avoids that.
11. **Inbound `acct` user via `channel originate`** arrives with an empty calling
    number (the originate has no caller id), and the account link shows in the
    peer's list as an empty node name (`RPT_LINKS=1,T`).
12. **tcpdump**: packets of the last milliseconds are lost without
    `--immediate-mode`, and the pcap header is written before the socket is
    attached; the agent waits for tcpdump's "listening" line.
