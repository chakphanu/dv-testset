# P25 network (P25Reflector / P25Gateway): obligations of the reflector side

What a P25 reflector owes the gateway clients that link to it on UDP
41000: P25Gateway (behind MMDVMHost, Pi-Star, WPSD, DVSwitch
MMDVM_Bridge), DroidStar, and the MMDVM_CM cross-mode tools. Each item is
numbered `P-P25-NN`; the cases are in `cases/proto/test_p25_network.py`
(markers `proto`, `rig`, `p25`), rows at the end of this file.

The wire format has no published specification. Its record type codes
0x62..0x73 are the DFSI CAI voice frame types of TIA-102.BAHA, but the
byte layout inside each record is the Motorola V.24 (Quantar) variant
that amateur software reverse engineered; G4KLX said in 2022 that he has
no specification of it [S11]. The TIA-102 documents still define what the
fields mean (LDU1/LDU2, link control, encryption sync, IMBE, terminator),
so the Level column cites them for field meaning and says
`convention (impl)` for the transport.

Every row says where the obligation comes from: the spec text (version and
section), what the clients send / expect / tolerate, what the other
servers do (project at a commit, behaviour in our own words, no code
copied), what xlxd-ref does, and what DV-Router should do. xlxd is not a
P25 server: it only peers with a P25Reflector, connecting out (interlink
row `P25<tg> <ip>:41000 <module>`). On the rig the P25 endpoint a client
talks to is therefore P25Reflector (`p25-ref` / `p25-sut`) with xlxd
behind it; the xlxd column is about the records xlxd builds and accepts
through that peer link. The xlxd column was measured on 2026-10-30
(`out/20261030T060024Z-i10`, instance 10, transcoder with IMBE, all 40
cases passed with sut == ref): sections 1-3 measure the P25Reflector in
front of xlxd-ref, sections 4-5 xlxd-ref through it.

**Level**: MUST / SHOULD only where a spec says so; `convention (impl)`
where only implementations back it, naming the ones that agree;
`disputed` where they differ, naming who does what.

## How the cases judge

`cases/proto/test_p25_network.py` probes the P25 endpoint of the reference
chain (`DVT_P25_REF`, P25Reflector + xlxd-ref) and of the system under test
(`DVT_P25_SUT`) in parallel:

- **hb**: a spec MUST, asserted on both sides.
- **diff**: a convention the servers agree on; sut == ref.
- **dev**: servers disagree, or xlxd deviates from the spec or from what
  clients need: sut == ref under `DVT_SUT_PROFILE=xlxd`, else the
  profile's spec entry (`dvtest/specs/<profile>.py`, `"p25"` dict
  `{"P-P25-NN": {observed key: value}}`), skip "spec pending" without one.
- **spec (Bn)**: judged by the DV-Router behaviour spec (testlist B rows).

DV-Router's role (owner decision, 2026-10-30): its P25 edge serves
clients directly on UDP 41000 (P25Gateway, DroidStar; URFd-style) and
also stays a peer of P25Reflector. Server items (sections 1-3 and
P-P25-36) therefore probe the sut's own P25 server at `DVT_P25_SUT`
against the reference server P25Reflector (`DVT_P25_REF`, p25-ref);
xlxd has no P25 server, so under the xlxd profile `DVT_P25_SUT` is the
p25-sut P25Reflector and those rows compare two copies of one program.
Under another profile they run only when the profile declares
`SPEC["p25"]["server"] = True`, and skip "edge not ready" before that.
Peer items (sections 4-5) go through xlxd and the P25Reflector peered
with it (`DVT_P25_PEER_SUT`, default `DVT_P25_SUT`). The diff rows of
sections 1-3 compare with P25Reflector, which agrees with the other
servers on them; P-P25-10's byte-for-byte relay is recorded, and asserted
only under the xlxd profile.

Conventions: ids are big endian, 24 bits. Record sizes and IMBE offsets:
0x62/0x6B 22 B at 10, 0x63/0x6C 14 B at 1, 0x64..0x69 and 0x6D..0x72
17 B at 5, 0x6A/0x73 16 B at 4, terminator 0x80 17 B. "Silently
ignored" = no reply and no state change.

## Where the recommendation differs from xlxd

- P-P25-01..09, 12, 16-18, 36: xlxd is no P25 server at all; DV-Router
  serves gateways and DroidStar directly on UDP 41000 (one port per room).
- P-P25-23: unknown callsign -> a configured gateway id, not a hash.
- P-P25-24: complete the last LDU with silence before 0x80.
- P-P25-25: no lone 0x80 for an empty stream.
- P-P25-26: pad short calls to one superframe so MMDVMHost plays them.
- P-P25-28: correct LC/ES parity (recorded only).
- P-P25-35: do not transcode encrypted P25.
- P-P25-15: terminator after a silence timeout (B3); P25Reflector sends none.
- P-P25-31: carry a call that starts after 0x62 (xlxd drops records before the first 0x62).
