# Icom G3 terminal / access point: obligations of the reflector side

What a reflector that emulates an Icom **G3 gateway** owes an Icom radio in
**Terminal Mode** or **Access Point Mode**: the RS-MS3A (Android), RS-MS3I
(iOS) and RS-MS3W (Windows) apps with an ID-31/ID-51/ID-52/ID-50/ID-4100,
and radios with a built-in DV gateway function (IC-705, IC-9700). The
radio believes it talks to an RS-RP3C gateway; the reflector answers its
position and route queries (UDP 12346, 12345) and exchanges D-STAR voice
with it in the G2 `DSVT` framing (UDP 40000). Each item is numbered
`P-G3-NN`; the cases are listed under "Testlist rows" at the end. The
spec key is `"g3"`; DV-Router has no G3 edge yet, so the cases skip under
the dvrouter profile until `SPEC["g3"]["server"]` is True.

DV-Router is a server for real clients, so the client side is the
contract: where xlxd differs from what Icom's documents and the clients
expect, the "Recommended for DV-Router" column follows them. Columns:
spec text, clients (Icom documents, closed apps; no published captures),
other servers (project at a commit, behaviour in our own words, no code
copied), xlxd-ref ("measured" cites the run of `cases/proto/test_g3.py`,
`out/20261030T082358Z-i12` (short `082358Z`, profile g3, `--capture`,
dvcheck exit 0); xlxd-sut behaved the same in every case; "code" = read in
the xlxd source only).

**Level**: MUST / SHOULD only where a spec says so; `convention (impl)`
where only implementations back it; `disputed` where they differ;
`convention (XLX family)` for rules xlxd and URFd share.

There is no public G3 specification. Icom documents only what the user
configures; Icom even states that Terminal Mode cannot use a reflector
([B] p.18: Gateway CQ and call sign routing only). Reflector access works
because the reflector presents itself as a gateway repeater and answers
the route query for `/XLXnnnM` (JARL 4.2.1 (3): a `/` before a repeater
callsign in UR calls that repeater). The packet layouts below therefore
come from xlxd (G3 support by YO2LOJ, 2019) and URFd, which share it; the
voice framing is the G2 gateway-to-gateway `DSVT` of JARL 5.2.

## How the cases judge

`cases/proto/test_g3.py` probes xlxd-ref and the system under test in
parallel; the Judged column of the testlist rows says how (hb / diff /
dev / spec (Bn), as in `docs/protocols/mmdvm.md`; dev items take the
profile's `SPEC["g3"]["P-G3-NN"]`, skip "spec pending" without it). Under
a profile whose spec does not say `"server": True` every case skips.

The tester is the terminal: it binds UDP 40000 on its own address (the
reflector sends voice and `PING` only to the terminal's IP:40000), sends
presence and route queries from any port, and keeps 40000 open for the
whole case. Rig facts that shape the cases:

- One terminal per IP: xlxd and URFd key a G3 client by IP, so the tester
  (one address) is one terminal per reflector; it is a terminal of
  xlxd-ref and of xlxd-sut at the same time (different reflector IPs).
- xlxd drops every G3 client of an IP on any ICMP "destination
  unreachable" for that IP (P-G3-23). Other suites leave ports on the
  tester closed while xlxd may still send to them for about a second, so a
  G3 case sends its presence again right before it talks and waits 1.5 s
  after the previous case.
- The reflector's address in its replies is the destination of the query
  (no `xlxd.terminal` in the rig), i.e. its rig address, which is right for
  a tester on the same /24.
- Terminal callsigns are compared without their 8th character: a second
  terminal needs another base callsign (`STR024 T`), not `N0TEST U`.
- A second terminal (P-G3-27) is the relay `g3-term2` at `<net>.31`
  (`scripts/run.sh --profile g3`, `python -m dvtest.proto.g3 relay`).
- The operator blacklist of P-G3-05 is `DVT_XLXD_BLACKLIST=N0G3X`, written to
  both reflectors' `xlxd.blacklist`; no other suite uses that callsign.
- Deliberately malformed probes are bracketed with control-channel marks,
  so dvcheck reports them as warnings.

Run: `DVT_XLXD_BLACKLIST=N0G3X scripts/run.sh -m proto --profile g3 --capture -- cases/proto/test_g3.py`

## 1. Presence (UDP 12346)

Packet: request 32 B = 8 B header (byte 2 flags, byte 3 status) + a
callsign (8) + owner (8) + terminal callsign (8); reply 36 B = the 32
bytes with byte 2 = 0x80 and byte 3 = 0x00, then the gateway's IPv4
address (4 B, network order).

## 2. Route query (UDP 12345)

Packet: request 16 B = 8 B header (byte 2 bit 0x10 = repeater call) +
the destination callsign (8: 7 characters + module; all spaces = the
reflector); reply 36 B = header with byte 2 | 0x80 and byte 3 status (0x00
accepted, 0x01 rejected), UR (8), RPT1 (8), RPT2 (8), IPv4 (4).

| # | Obligation | Level | Spec / paper | Clients | Other servers | xlxd-ref observed | Recommended for DV-Router |
|---|---|---|---|---|---|---|---|
| P-G3-06 | A repeater-call query for the reflector + an open module is accepted: status 0x00, UR = reflector + module, RPT1 = reflector + `G`, RPT2 = reflector + module, the gateway IPv4 | convention (XLX family) | JARL7 4.2.1 (3) (`/` + repeater calls that repeater), 4.1.1 h (gateway rewrites to repeater + `G`) | the user dials UR `/XLXnnnM` (OARC, #140); the radio then keys up with the returned UR / RPT1 / RPT2 | URFd the same | measured: status 0, UR `XLX999 J`, RPT1 `XLX999 G`, RPT2 `XLX999 J`, the reflector's own address (082358Z) | as all |
| P-G3-07 | A routed call (bit 0x10 clear), a foreign callsign or a module that is not open is rejected: status 0x01, IPv4 0 | convention (XLX family) | [B] p.32 (`UR?`, `RPT?` replies) | the radio shows `RPT?` / `UR?` | URFd the same | measured: routed call and `XLX998 J` both status 1, IPv4 0.0.0.0 (082358Z) | as all |
| P-G3-08 | A query of any other size gets no reply | convention (XLX family) | not stated | n/a | URFd the same | measured: 15 and 17 B not answered (082358Z) | as all |
| P-G3-09 | A query with an all-space callsign is taken as the reflector | convention (XLX family) | not stated | n/a | URFd the same | measured: all spaces answered with UR / RPT2 `XLX999` + space and status 1 (no module) (082358Z) | as all |
| P-G3-10 | The reflector callsign on the G3 wire (route replies, RPT fields) | disputed | not stated | the user dials what the operator publishes (`/XLX...` for XLX, `/URF...` for URFd) | URFd its own callsign (`URF...`) | measured: `XLX999` (the rig reflector is XLX999 already, so the forced `XLX` prefix is not visible here) (082358Z) | the name users dial for this reflector (spec decision) |

## 3. Voice (UDP 40000, DSVT)

stream id 12-13, byte 14 0x80, radio header 15-55), voice 27 B (byte 4
0x20, byte 14 sequence 0..20, 0x40 on the last, 9 B AMBE, 3 B slow data).

## Where the recommendation differs from xlxd

| # | xlxd | Recommended for DV-Router | Why |
|---|---|---|---|
| P-G3-03 | presence carries the address of the last route query (0.0.0.0 before one) | the destination of this query | a terminal that sends presence first gets an unusable address |
| P-G3-05 | presence not gated | operator lists apply | Icom gateways admit only registered terminals |
| P-G3-17 | last frame replaced by 55 C8 7A + zeros / 25 1A C6 | pass the ingress payload | as DExtra / DCS |
| P-G3-21 | invalid RPT1 / RPT2 drop the header | drop on invalid MY only | RPT fields are rewritten anyway |
| P-G3-23 | any ICMP unreachable for the IP removes all its G3 clients | only port unreachable for 40000 | traffic to another device or port behind the same NAT kicks the terminal |
| P-G3-24 | `PING` only when all of G3 is idle | to every terminal every 10 s | a hole-punched terminal stops receiving minutes after it last talked |
| P-G3-25 | timeout checked only while G3 is idle; presence does not refresh | always checked; presence refreshes | an idle terminal on a busy reflector is never timed out, a present one may be |
| P-G3-28 | a failed G3 socket stops the reflector | G3 fails alone | URFd makes G3 opt-in |
| P-G3-19 | the talking terminal gets 9 frames of its own stream back (measured) | no echo (B9) | the radio would play its own voice |

## What the rig needs

- **Today, nothing for one terminal.** The rig's xlxd containers run with
  the default Docker capabilities, which include `NET_RAW`; both xlxd-ref
  and xlxd-sut log "G3 handler loaded 0 options from file
  /xlxd/xlxd.terminal" and no raw-socket error (for example
  `out/20261030T063823Z-i12/logs`). No `xlxd.terminal` (empty file) means
  the replies carry each reflector's rig address, which is right for the
  tester. Ports 12345, 12346 and 40000 are free inside both containers.
  The tester binds UDP 40000 on .30; no other suite uses that port.
- **P-G3-27, second terminal:** profile `g3` adds the service `g3-term2`
  (the `dvt-tester` image at `<net>.31`, entrypoint `python -m
  dvtest.proto.g3 relay`), which the case drives over UDP 40100.
- **P-G3-05, operator list:** `DVT_XLXD_BLACKLIST` (default empty) is written
  to both reflectors' `xlxd.blacklist` by `rig/xlxd-entry.sh` (built xlxd)
  or `scripts/run.sh` (prebuilt image) and passed to the tester.
- **P-G3-28** (no raw socket) needs an xlxd started with `cap_drop:
  [NET_RAW]`; out of scope for now (recorded from the code).
- **DV-Router:** the cases skip until `SPEC["g3"]["server"]` is True;
  when the G3 edge exists its container needs `NET_RAW` only if it also
  uses ICMP to detect gone terminals.
